## 项目通读与架构梳理（首次接手）
- 通读 website-monitor 全部 42 个 Go 文件（master 32 / monitor 10），两模块均 `go build ./...` 通过。
- 结论要点：
  - master = Web 管理端(18888) + UDP Server(18889) + BoltDB + 日志文件存储；monitor = UDP 客户端探针，靠 HTTP `/data/*` 拉配置。
  - 监测链路：配置变更 → `Servers.NoticeAll` 通知 → monitor 拉取 → 每秒 tick 递减 `RateItem` 计频 → ping/对照组健康校验 → Health/Random/Point 三类请求 → `|` 分隔 19 字段串经 UDP Put 上报 → master 按天写文件 + 报警入库/发邮件。
  - 存储无 SQL，全部 BoltDB 单文件 + 文件日志；monitor 全内存 sync.Map。
- 已识别 10 项关键缺陷，写入 `.workbuddy/memory/MEMORY.md`，其中最高优先级为 bolt 连接生命周期、面板同步 UDP 阻塞、scan.go 闭包捕获与除零、whois/ReadLog 空指针。
- 未做任何代码修改，等待用户指定迭代任务。

## 体验优化（4 项）
- 版本号：`app.yaml` 增加 `app.version`，`handler.ginH` 通过 `conf.YamlGetString("app::version")` 读取并注入 `.Version`，同时注入 `.RunType`；`__header__` 不再硬编码 `dev`，使用说明页增加运行模式行。改配置即可换版本，`constname.MasterVersion` 仅兜底。
- KPI 跳转：面板四个 `.stat` 改为 `<a>`，分别到 `/sites`、`/sites?seg=monitoring`、`/sites?seg=alert`、`/alert?seg=unread`；`sites.js` / `alert.js` 从 `location.search` 读 `seg`（白名单校验），切换筛选时 `history.replaceState` 同步 URL。hover 显示右箭头，危险数值保留红色。
- 弹窗居中：根因是 `modal-xl` 写在外层 `.modal`，CSS `max-width:700px` 压窄了 fixed 容器。已把所有模板的 `modal-lg/modal-xl` 从 `.modal` 移到 `.modal-dialog`，统一加 `modal-dialog-centered`；创建监测额外用 `modal-dialog-scrollable` + `.modal-wide`（720px），小视口内可滚动且保持居中。
- 密度切换：原来只有 `--row-h` 一个变量（44→36），几乎无感。现改为 `--d-*` 令牌组（页面留白、卡片内边距、KPI 字号、表头/行高、列表项、抽屉、表单间距、图表高度、侧栏项高），紧凑模式下页面 padding 26/22→16/12、行高 44→37、KPI 区 199→166、侧栏项 32→27。按钮 active 态加 `.on` 高亮，title 显示当前模式。
- 顺手修：`.status.alert` 与 Bootstrap `.alert` 类名冲突，导致报警行被 padding 撑到 70px、其他行 44px；状态修饰类改为 `danger`（home.html、sites.js、theme.css）。
- 验证：两模块编译通过；7 个 JS `node --check` 通过；临时 httptest 渲染全部页面 200；Chrome 无头截图核对面板（舒适/紧凑）、弹窗（1440/1280 视口）、`/sites?seg=monitoring`、`/alert?seg=unread`；临时把 app.yaml 版本改成 v9.9.9 验证页面确实读配置。
